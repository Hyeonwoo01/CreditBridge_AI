# P22 이의 신청 작성 (학생)

| 항목 | 내용 |
| --- | --- |
| URL | `GET /student/evaluations/{id}/appeal`, 제출 `POST /student/evaluations/{id}/appeal` (multipart: `reason`, `files` 최대 3개, `csrf_token`) |
| 역할 | 학생 (본인 과목만, 다른 학생·역할은 403) |
| 템플릿 | `student/appeal_form.html` (상단 메뉴는 "이의 신청" 선택 상태) |
| 최대 폭 | 기본 `max-w-[1280px]` |

## 상태

| 상태 | 표시 |
| --- | --- |
| 작성 가능 | 판정이 있고(직접 인정 제외) 이의 신청을 아직 하지 않음 → 작성 폼 |
| 신청 불가 (직접 인정·이미 처리된 이의 신청) | 작성 화면 대신 P04로 돌아가 빨강 플래시로 이유 + "판정에 대해 더 자세히 알고 싶다면 학과 사무실을 직접 찾아 문의해 주세요." 직접 POST해도 422로 거절 |
| 처리 중인 이의 신청 있음 | 폼 대신 파치먼트 상자 "이미 처리 중인 이의 신청이 있어요" + 신청 날짜·상태 + [처리 상황 보기](P21) |
| 판정 전 | 폼 대신 "아직 이의를 신청할 수 없어요 — 학과 교수의 판정이 확정된 뒤에…" |
| 제출 실패 | 422로 같은 화면, 빨강 오류 상자. 적은 사유는 그대로 남고 파일은 다시 골라야 함. 저장되는 것 없음 |
| 제출 성공 | P21로 이동 + 플래시 "이의 신청을 접수했어요. 학사처가 검토한 뒤 결과를 알려 드려요." 심사관에게 알림 |

## 근거 자료 처리

- 파일은 형식·용량·빈 파일·암호 PDF를 강의계획서 업로드와 같은 규칙으로 검사하고, 모두 통과해야 이의 신청과 함께 저장한다(`appeal_files`).
- 내려받기 `GET /appeal-files/{id}`: 학생 본인, 소속 기관 심사관, 담당 학과 교수만. `Content-Disposition: attachment`, `Cache-Control: no-store`.
- 심사관 P07, 교수 P12·학생 P04의 이의 신청 경과, 학생 P21에 파일 링크로 보인다.
- 개인정보 삭제 요청이 승인되면 원본을 지우고 파일 이름만 "(삭제됨)"으로 남는다.
