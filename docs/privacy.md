# 개인정보 처리 (FR-13, NF-01~NF-03)

CreditBridge AI가 학생 문서를 어떻게 저장·전송·삭제하는지 정리한다. 기관 도입 심사(FERPA) 때 이 문서를 근거로 설명한다.

## 무엇을 어디에 저장하나

| 데이터 | 저장 위치 | 비고 |
| --- | --- | --- |
| 원본 강의계획서·성적표 파일 | 객체 스토리지(S3 호환) | 운영은 `S3_SERVER_SIDE_ENCRYPTION=AES256` 또는 `aws:kms`로 저장 암호화. DB에는 파일 키만 |
| 강의계획서 추출 텍스트·구조화 결과 | `syllabi.raw_text`, `syllabi.extracted_json` | 강의 내용이며 학생 개인정보는 아님 |
| 성적표 과목·학점·성적 | `transcript_entries` | 이름·학번·생년월일은 저장하지 않고, 이름은 마스킹 값(`L** J****`)만 |
| AI 분석 결과·근거 구절 | `course_evaluations`, `evidence_spans` | 강의계획서 구절과 원문 위치 |
| 교수 판정·감사 로그 | `decisions`, `audit_logs` | 추가 전용. 사용자 id와 행위만 기록하고 이름·학번·성적은 넣지 않음 |

## 모델 입력과 로그

- 성적표는 `app/security/masking.py`가 이름·학번·생년월일을 가린 뒤에만 Claude에 보낸다 (NF-01, `tests/unit/test_injection_and_masking.py`, `test_transcript_is_masked_before_llm_and_linked`).
- 애플리케이션 로그와 예외 메시지에는 이름·학번·성적을 쓰지 않는다. 로그에는 id와 오류 종류만 남긴다.
- 웹 서버(uvicorn) 접근 로그는 쿼리 문자열을 지우고 경로만 남긴다. 심사 큐 검색어(`/review?q=`)에 학생 이름이 들어갈 수 있기 때문이다 (`app/logging_setup.py::DropQueryString`, `test_access_log_drops_query_string`). 리버스 프록시를 앞에 둘 때도 접근 로그 형식에서 쿼리 문자열을 빼거나 `q` 값을 가린다.
- 전송 구간은 TLS로 보호한다. 운영 배포 시 리버스 프록시에서 TLS 1.2 이상만 허용한다 (NF-02).

## 모델 학습에 쓰지 않음 (NF-03)

- CreditBridge AI는 학생 문서를 학습용 데이터로 따로 모으거나 내보내는 경로가 없다. 저장된 데이터는 해당 심사 건 처리와 감사에만 쓴다.
- Claude 호출은 Anthropic API(상용 이용 약관)로 한다. Anthropic은 상용 API로 받은 입력·출력을 기본적으로 모델 학습에 쓰지 않는다. 계약 전 최신 상용 약관과 데이터 보존 기간을 확인해 기관에 함께 제출한다.

## 삭제 요청

- 학생이 요청 화면에서 "내 문서 삭제 요청"을 누르면 처리 기한(`PRIVACY_DELETION_DAYS`, 기본 30일)이 정해지고 심사관에게 알림이 가요.
- 심사관은 진행 중인 심사와 보관 의무를 확인한 뒤 "처리 완료"로 넘기고, 기관 관리자가 승인하면 그 즉시 삭제돼요. 기한이 급하면 관리자가 심사관 처리 전에 승인할 수도 있어요.
- 지우는 것: 강의계획서·보완 자료·성적표 원본 파일, 추출 텍스트·구조화 결과, 성적표 과목 목록, 청크 (`services/privacy.py`, `test_privacy_request_review_and_admin_approval`).
- 기한이 지난 요청은 심사관·관리자 화면과 운영 통계에 "기한 초과"로 표시돼요.
- 삭제한 문서는 같은 문서 결과 재사용(content_hash)의 출처에서도 빠져요.
- 교수 판정과 감사 로그는 학사 기록이라 남아요. 여기에는 판정 결과와 판정 당시 AI 추천 요약만 있고 원본 문서는 없어요.
- 관리자 콘솔(`/admin/stats`)의 "데이터 보존 및 파기 정책" 카드가 이 절의 요약(처리 기한, 지우는 것, 남는 것, 학습 미사용)을 보여 줘요. 처리 기한은 `PRIVACY_DELETION_DAYS` 값을 그대로 읽어요. 이 절을 바꾸면 `stats.html`의 카드 문구도 함께 고쳐요.

## 화면별로 보이는 학생 정보

화면에는 그 사람이 업무에 필요한 만큼만 보여 준다. 학번·생년월일은 어느 화면에도 나오지 않는다.

| 화면 | 보는 사람 | 학생 신원 | 성적 | 비고 |
| --- | --- | --- | --- | --- |
| 편입 학점 시뮬레이션 리포트·과목 분석 결과 (`/student/...`) | 학생 본인 | 본인 이름(리포트 제목) | 본인 성적표 성적 | 남의 요청은 403 |
| 심사 큐 (`/review`) | 소속 기관 심사관 | 이름, 출신 대학 (이름으로 검색 가능) | 없음 | 학사처가 접수 건을 학생 단위로 확인하는 업무라 표시. 검색어는 저장하지 않고, 접근 로그에서도 쿼리 문자열을 지움 |
| 문서 삭제 요청 처리 (`/review/privacy`, `/admin/privacy`) | 심사관, 기관 관리자 | 학생 계정 이메일 | 없음 | 요청한 본인인지 확인하는 용도 |
| 교수 홈·판정 화면 (`/professor/...`) | 배정된 교수 | 없음 | 없음 | 강의계획서와 과목 정보만 보고 판정 (학생을 모르는 상태로 심사) |
| 판정 근거 리포트 (`/evaluations/{id}/report`) | 학생 본인, 심사관, 담당 교수 | 없음 | 없음 | 판정 교수 이름, 선택형 사유, 소명 메모가 나옴 |
| 관리자 콘솔·운영 통계 (`/admin/stats`, `/review/stats`) | 기관 관리자, 심사관 | 없음 | 없음 | 기관·학과 단위 집계만. 교수 개인별 지표는 만들지 않음. 최근 감사 로그의 처리자는 교직원만 이름·역할로, 학생은 "학생"으로 표시 (`test_admin_console_shows_recent_audit_without_student_names`) |
| 전체 감사 로그 (`/admin/audit`) | 기관 관리자 | 없음 (사용자 id) | 없음 | 기록 내용은 id·행위·결과·사유 코드뿐, 소명 메모는 감사 로그에 넣지 않음 |
| 기관 보조 바 집계 칩 | 심사관, 교수, 관리자 | 없음 | 없음 | 제출 요청·심사 대기·판정 완료 건수만. 학생 화면에는 없음 |

- 교수가 쓰는 소명 메모는 학생도 보는 판정 근거 리포트에 그대로 나간다. 사유 선택 창의 메모 칸 안내("이름·학번·성적은 적지 마세요")대로 판정 근거만 적는다.
- 화면 목업에 있던 "교수 화면의 학생 이름", 실제 인증을 받지 않은 FERPA·SOC2 배지는 넣지 않았다. 인증 배지는 실제 인증을 받은 뒤에만 표시한다.

## 알림

- 화면 알림과 메일(`SMTP_HOST`를 설정한 경우)에는 과목 코드와 처리 내용만 넣고 이름·학번·성적은 넣지 않아요.
- 메일은 받는 사람 본인의 계정 이메일로만 보내요.
