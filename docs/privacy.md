# 개인정보 처리 (FR-13, NF-01~NF-03)

CreditBridge AI가 학생 문서를 어떻게 저장·전송·삭제하는지 정리한다. 기관 도입 심사(FERPA) 때 이 문서를 근거로 설명한다.

## 무엇을 어디에 저장하나

| 데이터 | 저장 위치 | 비고 |
| --- | --- | --- |
| 원본 강의계획서·성적표·보완 자료·이의 신청 근거 자료 파일 | 객체 스토리지(S3 호환) | 운영은 `S3_SERVER_SIDE_ENCRYPTION=AES256` 또는 `aws:kms`로 저장 암호화. DB에는 파일 키만(`supplement_files`, `appeal_files`는 파일 키·원래 파일 이름·형식·크기) |
| 강의계획서 추출 텍스트·구조화 결과 | `syllabi.raw_text`, `syllabi.extracted_json`, `syllabi.page_offsets` | 강의 내용이며 학생 개인정보는 아님. `page_offsets`는 원본 PDF의 쪽별 글자 위치(숫자 목록)뿐 |
| 심사 건 내부 메모 | `evaluation_notes` | 심사관·담당 교수가 쓴 메모(1000자). 학생 화면·판정 근거 리포트(화면·PDF)에는 나오지 않음. 메모 칸에 "이름·학번·성적은 적지 마세요"를 안내하고, 감사 로그(`note.create`)에는 메모 id만 남기고 내용은 넣지 않음 |
| 성적표 과목·학점·성적 | `transcript_entries` | 이름·학번·생년월일은 저장하지 않고, 이름은 마스킹 값(`L** J****`)만 |
| AI 분석 결과·근거 구절 | `course_evaluations`, `evidence_spans` | 강의계획서 구절과 원문 위치 |
| 이의 신청 사유 | `appeals.reason` | 학생이 쓴 글(20~3000자). 작성 화면에 "이름·학번은 적지 마세요"를 안내하고, 근거 자료도 이름·학번을 가리고 올리도록 안내 |
| 화면 알림 | `notifications` | 과목 코드와 처리 내용만. 읽음 시각(`read_at`)은 학생 메뉴의 "새 결과" 숫자 계산에 씀 |
| 웹 푸시 구독 | `push_subscriptions` | 본인이 "푸시 알림 받기"를 누른 기기(브라우저)의 푸시 서비스 주소와 암호화 키. 끄거나 브라우저가 권한을 거두면 지움. 로그에는 구독 id만 남기고 주소는 남기지 않음 |
| 화면 언어 | `users.locale`, 쿠키 `cb_lang` | `ko`/`en` 값만. 알림·메일을 받는 사람 언어로 보내는 데 씀. 쿠키는 HttpOnly·1년, 개인을 식별하지 않음 |
| 교수 판정·감사 로그 | `decisions`, `audit_logs` | 추가 전용. 사용자 id와 행위만 기록하고 이름·학번·성적은 넣지 않음. 이의 신청은 첨부 파일 수만 기록(`appeal.submit`의 `files`) |

## 모델 입력과 로그

- 성적표는 `backend/security/masking.py`가 이름·학번·생년월일을 가린 글로만 AI(Claude 또는 GPT)에게 과목 줄을 뽑게 하고, 저장하는 것도 가린 이름뿐이다. 단 스캔 PDF·사진 성적표는 글자를 읽는 전사 단계에서 원본 이미지가 AI에 전달된다(미결 사항 H12) (NF-01, `tests/unit/test_injection_and_masking.py`, `test_transcript_is_masked_before_llm_and_linked`).
- 애플리케이션 로그와 예외 메시지에는 이름·학번·성적을 쓰지 않는다. 로그에는 id와 오류 종류만 남긴다.
- 웹 서버(uvicorn) 접근 로그는 쿼리 문자열을 지우고 경로만 남긴다. 심사 큐 검색어(`/review?q=`)에 학생 이름이 들어갈 수 있기 때문이다 (`backend/logging_setup.py::DropQueryString`, `test_access_log_drops_query_string`). 리버스 프록시를 앞에 둘 때도 접근 로그 형식에서 쿼리 문자열을 빼거나 `q` 값을 가린다.
- 전송 구간은 TLS로 보호한다. 운영 배포 시 리버스 프록시에서 TLS 1.2 이상만 허용한다 (NF-02).

## 모델 학습에 쓰지 않음 (NF-03)

- CreditBridge AI는 학생 문서를 학습용 데이터로 따로 모으거나 내보내는 경로가 없다. 저장된 데이터는 해당 심사 건 처리와 감사에만 쓴다.
- AI 호출은 설정(`LLM_PROVIDER`)에 따라 Anthropic API(Claude) 또는 OpenAI API(GPT)의 상용 이용 약관으로 한다. 두 회사 모두 API로 받은 입력·출력을 기본적으로 모델 학습에 쓰지 않는다고 밝히고 있지만, 남용 감시 등을 위한 보존 기간은 회사·계약마다 다르다. 실제로 쓰는 쪽의 최신 상용 약관과 데이터 보존 기간을 계약 전에 확인해 기관에 함께 제출한다 (학생 성적표·강의계획서 내용이 그 회사로 전송된다).

## 삭제 요청

- 학생이 요청 화면에서 "내 문서 삭제 요청"을 누르면 처리 기한(`PRIVACY_DELETION_DAYS`, 기본 30일)이 정해지고 심사관과 기관 관리자에게 알림이 가요(관리자 "삭제 승인" 배지에도 바로 나와요).
- 심사관은 진행 중인 심사와 보관 의무를 확인한 뒤 "처리 완료"로 넘기고, 기관 관리자가 승인하면 그 즉시 삭제돼요. 기한이 급하면 관리자가 심사관 처리 전에 승인할 수도 있어요.
- 승인하면 그 편입 요청은 **종료**(closed)돼요. 학생 화면은 종료 안내로 바뀌고 더 올리거나 심사를 요청할 수 없으며, 심사 큐·교수 목록에서 빠지고 담당 교수에게 종료 알림이 가요. 이미 내린 판정과 감사 로그는 학사 기록으로 남아요.
- 지우는 것: 강의계획서·보완 자료·성적표·이의 신청 근거 자료 원본 파일, 추출 텍스트·구조화 결과·원본 쪽 위치표, 성적표 과목 목록, 청크, 심사 건 내부 메모, 학생이 쓴 이의 신청 사유 (`services/privacy.py`, `test_privacy_request_review_and_admin_approval`, `test_appeal_form_with_evidence_files`, `test_internal_notes_for_staff_only`, `test_deletion_also_removes_appeals_from_student_view`). 지운 뒤에는 근거 구절의 "원본 N쪽" 링크도 사라진다. 이의 신청 근거 자료는 파일 이름만 "(삭제됨)"으로 남는다.
- 성적표는 학생 계정에 하나(`student_transcripts`)이고 요청마다 과목 줄을 복사해 써요. 요청 문서 삭제는 그 요청의 사본(과목 목록)만 지우고 계정 성적표 원본·과목 줄은 남겨요(다른 요청과 다음 요청에 쓰기 위해). 성적표 과목 요청이면 같은 과목의 새 요청(초안)을 바로 준비해 학생이 강의계획서를 다시 낼 수 있어요(삭제된 이전 요청은 판정 기록과 함께 종료 상태로 남음). 계정 성적표를 바꾸면 이전 원본 파일은 지워요.
- 종료된 요청의 이의 신청은 학생 화면(이의 신청 목록·과목 화면)에서 함께 사라지고 다시 낼 수 없어요. 심사관 이의 신청 처리 목록에서도 빠져요. 이의 신청 행(상태·처리 결과)은 그 이의 신청으로 내린 재판정 기록이 가리키고 있어 남겨요. 이 규칙 전에 종료된 요청의 사유는 마이그레이션 0006이 지워요.
- 기한이 지난 요청은 심사관·관리자 화면과 운영 통계에 "기한 초과"로 표시돼요.
- 삭제한 문서는 같은 문서 결과 재사용(content_hash)의 출처에서도 빠져요.
- 교수 판정과 감사 로그는 학사 기록이라 남아요. 여기에는 판정 결과와 판정 당시 AI 추천 요약만 있고 원본 문서는 없어요.
- 관리자 콘솔(`/admin/stats`)의 "데이터 보존 및 파기 정책" 카드가 이 절의 요약(처리 기한, 지우는 것, 남는 것, 학습 미사용)을 보여 줘요. 처리 기한은 `PRIVACY_DELETION_DAYS` 값을 그대로 읽어요. 이 절을 바꾸면 `stats.html`의 카드 문구도 함께 고쳐요.

## 계정 만들기와 비밀번호

- 계정은 기관 관리자가 계정 CSV(`email,name,role,department`)로 만들거나, 운영 시작 때 `scripts/create_admin.py`로 첫 관리자를 만든다. 학생이 스스로 가입하는 경로는 없다.
- CSV에는 비밀번호 열이 없다. **메일 발송이 설정돼 있으면** 새 계정의 비밀번호를 아무도 모르는 값으로 두고, 각자의 메일로 비밀번호 설정 링크(72시간·한 번만 사용)를 자동으로 보낸다. 관리자는 비밀번호를 보거나 전달하지 않는다. **메일 발송이 없으면** 새 계정마다 임시 비밀번호(12자, 헷갈리는 글자 제외)를 만들어 가져온 직후 화면에 한 번만 보여 준다(관리자가 CSV로 받을 수 있음). 어느 쪽이든 서버에는 Argon2 해시만 저장하고, 그 화면은 `Cache-Control: no-store`로 브라우저·프록시 캐시를 막는다.
- 임시 비밀번호 계정은 첫 로그인 뒤 새 비밀번호(10자 이상)로 바꾸기 전까지 다른 화면과 API를 쓸 수 없다 (`users.must_change_password`, `security/session.py`).
- 임시 비밀번호를 받은 경우(메일 미설정) 관리자는 그 파일을 본인에게만 전달하고, 전달이 끝나면 지운다. 임시 비밀번호 자체를 메일로 보내지는 않는다(메일함에 비밀번호가 글자 그대로 남지 않도록 링크만 보낸다).
- 비밀번호 재설정(메일): 로그인 화면에서 이메일을 적으면, 등록 여부와 상관없이 같은 안내를 보여 준다(계정 존재 여부를 알려 주지 않음). 같은 계정에는 5분에 한 번만 보낸다. 링크의 토큰은 서버에 저장하지 않는 서명 값으로, 30분(새 계정·관리자 초기화 링크는 72시간)이 지나거나 비밀번호가 바뀌면(재설정 완료 포함) 쓸 수 없다. 토큰은 메일을 보내는 작업 안에서 만들어 DB·작업 큐·로그에 남지 않고, 접근 로그는 쿼리 문자열을 지운다. 재설정 화면은 캐시하지 않고 `Referrer-Policy: no-referrer`로 외부 요청에 주소가 새지 않게 한다. 메일 본문에는 이름을 넣지 않는다 (`services/auth.py`, `test_email_reset_link_works_once_and_ends_other_sessions`).
- 비밀번호 재설정(관리자): 기관 관리자가 소속 사용자의 비밀번호를 초기화하면, 메일 발송이 설정돼 있을 때는 비밀번호를 무효로 하고 사용자 메일로 설정 링크(72시간)를 자동으로 보낸다(관리자에게 비밀번호를 보여 주지 않음). 메일이 없으면 임시 비밀번호를 화면에 한 번만 보여 주고 다음 로그인 때 바꾸게 한다. 감사 로그에는 대상 사용자 id와 방식만 남긴다 (`account.password_reset_by_admin`).
- 로그인 실패 잠금: 연속 5번 틀리면 1분 동안 로그인을 막고(맞는 비밀번호도 거절), 그 뒤로도 틀려 연속 10번이 되면 비밀번호를 아무도 모르는 값으로 바꿔 무효로 한다. 이때 다른 기기의 로그인도 끊기고, 메일 발송이 설정돼 있으면 재설정 링크를 자동으로 보낸다(없으면 관리자 재발급). 로그인에 성공하거나 재설정하면 횟수는 0이 된다 (`users.failed_logins`·`locked_until`, `services/auth.py::login_attempt`, `test_login_lockout.py`).
- 잠금 안내는 실제로 있는 계정에만 나오므로 그 이메일이 가입돼 있는지 짐작할 수 있다. 무차별 대입을 막는 쪽을 택했고, 없는 이메일은 몇 번을 틀려도 같은 일반 안내만 보여 준다. 감사 로그에는 잠금(`auth.lockout`)과 초기화(`auth.lockout_reset`, 실패 횟수만)를 남긴다.
- 계정 비활성화: 졸업·퇴직·휴학한 사람은 기관 관리자가 `/admin/data`에서 이메일로 비활성화한다. 판정·감사 기록이 그 사람을 가리키므로 계정은 지우지 않는다. 비활성 계정은 로그인·비밀번호 재설정·알림 메일이 막히고 남은 로그인도 바로 끊긴다. 비밀번호가 맞을 때만 "비활성화된 계정" 안내를 보여 주고, 틀리면 일반 안내만 보여 실패 횟수도 세지 않는다. 감사 로그에는 대상 사용자 id와 넘긴·비운 심사 건수만 남긴다 (`account.deactivate`·`account.reactivate`, `test_account_active.py`). 관리자 화면에는 비활성 계정 수만 나오고 목록은 보여 주지 않는다.
- 비밀번호가 바뀌면(변경·재설정·관리자 재발급·실패 10회 초기화) 다른 기기에 남아 있던 로그인 세션은 끊긴다. 세션에 비밀번호 해시의 짧은 지문을 넣어 맞지 않으면 다시 로그인하게 한다.
- 올린 CSV 파일 자체는 저장하지 않고, 검증을 통과한 행만 계정·과목으로 저장한다. 감사 로그에는 만든·건너뛴 건수만 남기고 이름·이메일은 넣지 않는다 (`account.import`, `test_account_import_gives_one_time_passwords_and_forces_change`).
- 과목별 기준 강의계획서는 대학 공개 자료라 학생 개인정보가 아니다. 학생 문서와 같은 객체 스토리지에 저장하고, 문서 속 지시 문구는 AI 입력에서 빼고 넣는다.

## 알림

- 화면 알림과 메일(`SMTP_HOST`를 설정한 경우)에는 과목 코드와 처리 내용만 넣고 이름·학번·성적은 넣지 않아요.
- 메일은 받는 사람 본인의 계정 이메일로만 보내요.
- 웹 푸시(VAPID 키를 설정한 경우)도 화면 알림과 같은 글과 화면 주소만 담아요. 내용은 받는 기기의 키로 암호화돼 브라우저 회사의 푸시 서비스(예: Google FCM, Apple, Mozilla)를 거쳐 전달되고, 푸시 서비스는 내용을 볼 수 없어요. 본인이 켠 기기에만 보내고, 비활성 계정에는 보내지 않아요 (`services/push.py`, `test_web_push.py`).
- 알림은 한국어 원문으로 저장하고, 화면과 메일에서 보는 사람·받는 사람의 언어(`users.locale`)로 바꿔 보여 줘요. 번역해도 들어가는 값(과목 코드·건수)은 같아요 (`backend/i18n.py::translate_stored`).
- 매일 보내는 기한 알림도 같은 규칙이에요. 건수와 과목 코드만 넣고(예: "기한 알림: 판정 기한이 지난 심사 1건"), 학생 이름은 교직원 알림에 넣지 않아요. 같은 종류는 하루 한 번만, 비활성 계정에는 보내지 않아요 (`services/reminders.py`, `test_reminders.py`).
- 메뉴 숫자 배지는 화면을 그릴 때마다 다시 세고 따로 저장하지 않아요(`views.nav_badges`, `web/nav.py`). 숫자는 그 역할이 원래 볼 수 있는 범위 안에서만 세요: 학생은 본인 데이터, 교수는 본인에게 배정된 심사, 심사관·관리자는 소속 기관 건. 그래서 배지로 새로 드러나는 정보는 없어요.
- 학생 배지가 세는 것:
  - 채워야 할 서류 수: 본인 편입 요청의 보완 자료 요청·성적표·강의계획서·과목 연결 상태
  - 이의 신청할 수 있는 과목 수: 본인 과목 중 판정이 확정됐고 처리 중인 이의 신청이 없는 과목
  - 새 판정·이의 신청 결과 수: 본인 알림 중 판정 결과(`decision.created`)와 이의 신청 결과(`appeal.accepted`·`appeal.dismissed`·`decision.redecided`)의 안 읽은 개수. 해당 과목 화면이나 이의 신청 화면을 열면 그 알림을 읽음으로 바꿔요(`notifications.mark_seen`).
- 교직원 배지는 알림을 쓰지 않고 심사·이의 신청·삭제 요청·과목 데이터의 상태로 세요. 학생 배지 중 "새 결과" 숫자만 알림의 읽음 여부를 써요.
